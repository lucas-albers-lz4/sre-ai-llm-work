## LLM Ops Reliability
- Vendor support window: four most recent minor lines, roughly one month of coverage per line — take within-line patches as drop-ins and budget the minor-line move monthly, before the pinned line ages out
- Provider parity breaks in the shared forwarding path: `encoding_format=None` rejected every vLLM embedding through the gateway for ~3 hours while OpenAI stayed green — filter-to-omit falsy params at the shared boundary and assert the exact wire payload per backend family, testing the non-default provider
- A green eval can be a replay: promptfoo caches provider responses 14 days by default — use `--no-cache` with `--repeat` for variance runs, invalidate before post-upgrade and canary-vs-control comparisons, and size CI spend for the never-cached failing tail
- Six documented configs pass while verifying nothing: `threshold: 0`, `weight: 0`, bare `llm-rubric`, bare `context-faithfulness`/`context-recall` (default threshold 0), a missing guardrails signal, and a fail-open JS trace guard — every score-producing assertion gets an explicit non-zero threshold and every suite a deliberately-wrong negative control
- Model-graded defaults are per-type, not per-family: `factuality` passes category B by default, so an answer that appends unverified claims to a correct core passes — set `superset: 0`; g-eval arrays average criteria (one 0.0 plus three 1.0 clears a 0.7 threshold) and cost two judge calls per assertion
- The judge is unpinned by default: the grading provider comes from ambient credentials, assertion-level shorthand drops the provider's `config`, GPT-5-series judges ignore `temperature=0`, and `answer-relevance` hides a second unpinned embedding provider — pin every model artifact behind a verdict
- Grade the route, not just the reply: the trajectory assertion family reads OTel span data, and a missing trace must fail the run — the built-in family throws, the vendor's own custom-JS example `return true`s
- Generated datasets are the mutable external reference the hermeticity rule prohibits: `promptfoo generate dataset` seeds nothing, and `-w` rewrites the gate's inputs in place — emit with `-o`, commit as a `file://` fixture, record the synthesis model, never `-w` a deploy gate
- Always-on judging deploys as a scoped Rule (filters + sampling + evaluators), validated on representative production observations first; the sampling rate is the cost dial, set from trailing volume and estimated judge cost, with batch re-scoring for rubric changes
- Alert on quality rates alongside latency and cost: a boolean score's average is its true-share, so a policy-check or hallucination rate thresholds directly — pair a warning and alert threshold with a deliberate no-data mode, since the default treat-missing-as-0 is silent
- A request-path guardrail is an availability dependency: `unreachable_fallback: fail_closed` and `fail_on_error: true` are the defaults, and `fail_on_error: false` is a complete bypass visible only as a critical-level fail-open log line — give it its own error-rate SLO
- Gateway governance is per-method and per-window: only `message/send` and `message/stream` traverse the log, guardrail, and spend paths while `tasks/*` bypasses them; agent-loop caps fail open without the outbound trace-id flag, reject one call late, surface as `budget_exceeded` 429s, and reset on a 1-hour TTL
- Spend and routing attribution gets named levers: a prompt store's `prompt_template_model` and params override the client unless ignored, router decisions log at request granularity with `cause=`, session affinity pins a session to its first-turn tier, and a semantic cache's similarity threshold is a correctness knob — while an adaptive router without Postgres forgets its learning on restart
- Streamed traffic is usage-blind by default: pass `stream_options={"include_usage": True}` and read the final usage chunk, label `completion_cost` output an estimate, stream pass-through bodies nothing downstream inspects, and buffer only what the spend logger and guardrails must read

## Security and Trust
- Skills can bound their own blast radius: an author-written `allowed-tools` frontmatter allowlist is machine-checkable and stronger than a post-install trust call
- Gateway-side tool authorization is the runtime half of the rbac/bfla/bola checklist — the guardrail is handed both `tools` and `tool_calls`, but only on `/v1/chat/completions`, `/v1/responses`, and `/v1/messages`
- An agent gateway's default is full access: unconfigured key and team means access to *all* agents, key-and-team restrictions intersect, ACL group tags persist through a dashboard/DB path no config diff can review, adding an agent to a group silently widens access, and hiding a skill from the served card is not authorization
- A guardrail gate reads a signal, it does not run a guardrail: a missing `guardrails` field passes at score 1, and the `purpose: redteam` override force-passes detect-only bypasses so an unsafe response reports `success: true` and exits 0
- A classifier gate's detector is a dependency with a lifecycle — the recommended prompt-injection detector is archived, and its label-bound thresholds must be re-validated rather than reused when the detector changes
- A guardrail is an egress boundary: `request_headers` is allowlist-only and non-listed headers arrive as `[present]` — enumerate the header names and identity fields the guardrail actually needs instead of passing the lot
- Gateway credential routing: declare, don't infer — LiteLLM's MCP postmortem replaces field-sniffing with a declared auth mode and one typed, exhaustive resolver where ambiguity resolves to "stop"
- A SHA pin says what you have, an attestation says who built it: verify provenance with `gh attestation verify`, resolve tags to commits before pinning, and treat pre-hardening releases (before v0.1.8) as unpinned
- Job-level isolation is not step-level isolation — a step running PR-controlled code can persist `$GITHUB_PATH`, `$GITHUB_ENV`, or `$HOME` writes that later credential-holding steps inherit, so the scan belongs in its own job
- Security-scan gating: set `minSeverity` as the alert-fatigue control, choose `diffsOnly` by placement (blocking per-PR gate versus nightly full scan), gate on the scan's completion signal rather than its findings count so a skipped scan is not published as a clean SARIF, and keep fork PRs default-deny behind an explicit maintainer override
